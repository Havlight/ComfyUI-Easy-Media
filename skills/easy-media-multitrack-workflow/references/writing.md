# 写提示词与多段规划

H3 的提示词有固定的写法。规划与动笔前依序必读：
1. 不分风格都成立的分镜、声音与通用写法：[craft.md](craft.md)；
2. 拍摄模式、运镜防退化与跨镜衔接：[camera.md](camera.md)；
3. 对应任务 `mode` 的官方单段格式指南（见下表）；
4. 扫描 [modules/](modules/) 首行挑选相符的画风／影片类型模块（见下方「模块」）。

## 用哪份指南

| 任务 `mode` | 指南 | 这段怎么生成 |
|---|---|---|
| `ref`、`edit` | [prompts/ref.md](prompts/ref.md) | 参考图片、视频、音频生成（`ref`），或编辑视频（`edit`） |
| `default` | [prompts/base.md](prompts/base.md) | 没有图片是 T2VA；第一张图是首帧（I2VA）；两张以上时最后一张是尾帧（FL2VA），中间的图不会用到 |
| `l2v` | [prompts/base.md](prompts/base.md) | 最后一张图是尾帧（L2VA），其他图不会用到 |
| `passthrough` | 不需要 | 不采样，直接输出来源视频 |

- 指南是写给「改写用户描述」的模型看的：你从用户需求整理出的这段内容，就是指南说的原始描述。
- `<Video N>`、`<Audio N>` 只在 `ref`、`edit` 有意义；`default`、`l2v` 只用图片当画面帧，提示词改用 [prompts/base.md](prompts/base.md) 的 `integrated_multimodal_description` 结构（不写 `subject_definitions`、`<Subject N>` 与 `retention_analysis`）。

## 标签与秒数

`apply` 报告的 `tasks[].labels` 列出每段每个标签对应的素材，提示词里的标签照它写：

```json
{ "<Picture 1>": "previous task's last frame", "<Picture 2>": "alice.png",
  "<Video 1>": "dance.mp4 (video track v1, track window)", "<Audio 1>": "soundtrack of <Video 1>" }
```

- 编号规则（公用图在前、锁定视频固定是 `<Video 1>`、视频原声先占 `<Audio N>`）由转换计算，不用自己推。改了参考素材或轨道后重新转换再核对；转换不占 GPU。
- `default`、`l2v` 的标签会注明 `first frame`、`last frame`，不会用到的图写 `unused`。
- 报告的 `seconds` 是对齐帧格后的实际长度（例如 24fps 下 5 秒的独立镜头是 5.17 秒，14 秒是 14.38 秒）。对齐句的秒数、`[Shot N] At MM:SS.mmm` 的切镜时间，以及段内时间窗 `At MM:SS.mmm-MM:SS.mmm,` 的末尾秒数，一律以 `seconds` 为准（勿直接填未对齐的 `.000` 整数秒）。
- 接续段的上一段画面在 latent 层接上，不占标签，不用为它写 `<Video N>`。分页里已有的 `previous_frame` 会占一个 `<Picture N>`。

## 不能看图时

参考图的外观从文件名和用户给的描述得知；不知道的细节不写，不要编。

## 分镜与分段

- 用户给了分镜就照着分段；只给目标时自己规划。用户想先看分镜时，先列表格（id、秒数、mode、接续方式、内容、素材）再写提示词。
- 一段一个主要事件。同一场景、共用同一组参考素材的变化（如双人正反打对话、快切反应），可以在一段内用 `[Shot N]` 切镜；需要更换或增减参考素材（如出场人物增减、服装阶段切换、换构图参考图／首帧），或要接着上一段的画面时，分成不同任务。
- 时间连续接着上一段演用 `context_anchor`（段内切出将持续多段的新构图时可标 `anchor: "restart"`）；换场景、时间跳跃／省略中间过程直接从第 0 秒切入新状态，或用首帧 `I2VA` 时用 `shot`。
- 有锁定的歌曲或影片时，各段加起来不要超过它的长度；超过时转换会警告。

## 多段一致

模型每次只看到一段的提示词，看不到前后段。

- 每段都完整描述主体，不写「同上」「同一个女孩」。无论有参考图的 `<Subject N>` 或无参考图的常驻配角／伴侣，同一个角色每段都固定用同一组英文外观、体格、肤色与当前衣着短语；风格开头那句每段也一样。
- `<Subject N>`、`(S1)` 在每段内各自编号；同一个角色尽量每段用同一个编号，比较不会乱。
- 接续段（`context_anchor`／`context_drift`）的 `[Shot 1]` 直接从上一段末帧正在进行的姿势、动作方向、位置、机位与光线续写，不在开头重新铺垫待命入场。
- 同一个角色或场景要每段都有同一张参考图时，设为公用（`shared: true`）。**例外**：说话音色参考 `<Audio N>` 仅挂在有 `<d>` 台词的任务上，不设 `shared: true` 铺满无台词段落（见 [craft.md](craft.md)「声音三层职责分离」）。
- 台词或歌词跨段时按时间拆开，每段只写自己时间范围内的部分。锁定的歌曲默认不是参考标签（报告里没有对应的 `<Audio N>`）；要角色对嘴时，在 `<d>` 写这段时间里的歌词，唱歌的角色给 `(S1)`。

## 模块

[modules/](modules/) 里每份文件是一种画风或影片类型的写法，只在用得上时读：

1. 规划前列出 `modules/` 的文件，读每份的第一行（`适用：…`）。
2. 跟用户的要求或参考素材相符的才读全文。可以同时用几份，例如一份画风加一份影片类型；同一类有两份都像时问用户。
3. 都不相符就不用模块，只照 [craft.md](craft.md)、[camera.md](camera.md) 与指南写，不要套最接近的那份。
4. 模块不改格式（字段、标签、切镜语法照指南）；写法跟 craft.md 不同时（例如切镜多寡），以模块为准。
5. 交付时说明用了哪些模块。

文件名前缀表示类别：`2d-`、`3d-`、`live-`（画风），`type-`（影片类型，如 NSFW、MV）。

## 选用层

[optional/](optional/) 里是有价值、但属于个人审美预设或没在这里验证的内容（角色视角偏好预设、特殊光影、难做的运镜、特效等），每份第一行写 `内容：…；不默认的原因：…`：

1. 不默认套用：规划前可列出 `optional/` 文件并只读第一行摘要；若发现与当前影片类型或用户需求相关的选用项（例如某类预设代号或整圈环绕），可在对齐时顺带提一句代号／名称由用户决定要不要用。
2. 只有用户明确指名某一份（如说「套用预设 A」）或要求查看选用层时，才读该份全文并启用；交付时说明用了哪份。

## 只写短描述

用户要求，或模型不擅长长格式时：每段写一两句描述（主体、动作、镜头），交给工作流里的 `MultiTrack Prompt Enhancer` 节点改写。模板没有这个节点时，就要写完整的提示词。

## 修改写法与模块

craft.md、camera.md、模块与选用层只在用户要求时修改。用户要加内容时：

- **先筛**：跟人物外貌、身材有关的偏好不收，人物长相由参考图或用户决定。光影、运镜、人物态度偏好、特效这类审美选择，或有价值但没验证、跟现有写法冲突的，说明理由，建议放进选用层，由用户决定。来源是别人的 skill 或提示词时也一样，不照单全收。
- **放哪里**：换任何画风、运镜、类型都成立，而且是模型的行为或限制的，放进 craft.md 或 camera.md 相关的那一节，能并进现有那条就并；只在某种画风或影片类型成立的，放进对应的模块，没有就新建一份。指南写过的不再写。
- **模块的写法**：第一行 `适用：…`，写什么要求或素材用它；只写跟 craft.md／camera.md 不同或它们没有的；内容来自跑过、效果好的提示词；不写专案经过、日期或个人偏好；不硬编码具体 `optional/` 文件路径；可附短范例，提示词照指南用英文，台词保留原文。
- **删除模块或选用层的一份**就是删掉那份文件，没有别的地方要改。用户实际跑过、效果好的选用层内容，可以照用户的意思移进模块或 craft.md。
- **整理**：用户要求整理时，列出打算合并、改写、删除的地方，用户同意后才改。
