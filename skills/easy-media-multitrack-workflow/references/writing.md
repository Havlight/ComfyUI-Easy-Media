# 写提示词与多段规划

H3 的提示词有固定的写法。两份指南讲怎么写好**一段**；本文件补上多段影片需要知道的事，以及我们管线的规则。不分风格都成立的写法见 [craft.md](craft.md)；画风、运镜、影片类型的写法在模块里，见下面「模块」。

## 用哪份指南

| 任务 `mode` | 指南 | 这段怎么生成 |
|---|---|---|
| `ref`、`edit` | [prompts/ref.md](prompts/ref.md) | 参考图片、视频、音频生成（`ref`），或编辑视频（`edit`） |
| `default` | [prompts/base.md](prompts/base.md) | 没有图片是 T2VA；第一张图是首帧（I2VA）；两张以上时最后一张是尾帧（FL2VA），中间的图不会用到 |
| `l2v` | [prompts/base.md](prompts/base.md) | 最后一张图是尾帧（L2VA），其他图不会用到 |
| `passthrough` | 不需要 | 不采样，直接输出来源视频 |

- 指南是写给「改写用户描述」的模型看的：你从用户需求整理出的这段内容，就是指南说的原始描述。
- `<Video N>`、`<Audio N>` 只在 `ref`、`edit` 有意义；`default`、`l2v` 只用图片当画面帧。
- 选 `ref` 还是 `default`（首帧 I2V）：对话、单人表演、需要绑定 `<Audio N>` 音色或多张设定图组合时用 `ref`；只有手边已经有画面比例相符、人物与结构都正确的单格成品图（且该段不需要音色参考与额外设定图）时，才适合用 `default` 当首帧锁死起始结构。

## 标签与秒数

`apply` 报告的 `tasks[].labels` 列出每段每个标签对应的素材，提示词里的标签照它写：

```json
{ "<Picture 1>": "previous task's last frame", "<Picture 2>": "alice.png",
  "<Video 1>": "dance.mp4 (video track v1, track window)", "<Audio 1>": "soundtrack of <Video 1>" }
```

- 编号规则（公用图在前、锁定视频固定是 `<Video 1>`、视频原声先占 `<Audio N>`）由转换计算，不用自己推。改了参考素材或轨道后重新转换再核对；转换不占 GPU。
- `default`、`l2v` 的标签会注明 `first frame`、`last frame`，不会用到的图写 `unused`。
- 报告的 `seconds` 是对齐帧格后的实际长度（例如 5 秒的独立镜头是 5.17 秒）。对齐句的秒数和 `[Shot N] At MM:SS.mmm` 的切镜时间都以它为准。
- 接续段的上一段画面在 latent 层接上，不占标签，不用为它写 `<Video N>`。分页里已有的 `previous_frame` 会占一个 `<Picture N>`。

## 不能看图时

参考图的外观从文件名和用户给的描述得知；不知道的细节不写，不要编。

## 分镜与分段

- 用户给了分镜就照着分段；只给目标时自己规划。用户想先看分镜时，先列表格（id、秒数、mode、接续方式、内容、素材）再写提示词。
- 一段一个主要事件。同一批出场人物、共用同一组参考图的快切反应，可以在一段内用 `[Shot N]` 切镜；出场人物增减（须撤掉未出场角色参考图）、服装阶段改变、正反打换人说话、换构图参考图／首帧，或要接着上一段的画面时，分成不同任务（切镜设 `continuity: "shot"`），切点精准且台词互不抢时。
- 有锁定的歌曲或影片时，各段加起来不要超过它的长度；超过时转换会警告。

## 多段一致

模型每次只看到一段的提示词，看不到前后段。

- 每段都完整描述主体，不写「同上」「同一个女孩」。同一个角色每段用同一句外观描述，风格开头那句每段也一样。
- `<Subject N>`、`(S1)` 在每段内各自编号；同一个角色尽量每段用同一个编号，比较不会乱。
- 接续段的 `[Shot 1]` 从上一段结束时的状态写起（姿势、位置、镜头方向、光线），再接着演。
- 同一个角色或场景要每段都有同一张参考图时，设为公用（`shared: true`）。
- 台词或歌词跨段时按时间拆开，每段只写自己时间范围内的部分。锁定的歌曲默认不是参考标签（报告里没有对应的 `<Audio N>`）；要角色对嘴时，在 `<d>` 写这段时间里的歌词，唱歌的角色给 `(S1)`。

## 模块

[modules/](modules/) 里每份文件是一种画风、运镜或影片类型的写法，只在用得上时读：

1. 规划前列出 `modules/` 的文件，读每份的第一行（`适用：…`）。
2. 跟用户的要求或参考素材相符的才读全文。可以同时用几份，例如一份画风加一份运镜；同一类有两份都像时问用户。
3. 都不相符就不用模块，只照 [craft.md](craft.md) 与指南写，不要套最接近的那份。
4. 模块不改格式（字段、标签、切镜语法照指南）；写法跟 craft.md 不同时（例如切镜多寡），以模块为准。
5. 交付时说明用了哪些模块。

文件名前缀表示类别：`2d-`、`3d-`、`live-`（画风），`camera-`（运镜），`type-`（影片类型，如 vlog、MV）。

## 选用层

[optional/](optional/) 里是有价值、但属于审美选择或没在这里验证的内容（光影、难做的运镜、特效等）。不主动读，也不在「模块」的选择范围里：用户说要看选用层或指名某一份时才读，交付时说明用了哪份。用户的要求跟某一份相关时（例如要整圈环绕），可以提一句有这份，由用户决定要不要用。每份第一行写内容与不默认的原因。

## 只写短描述

用户要求，或模型不擅长长格式时：每段写一两句描述（主体、动作、镜头），交给工作流里的 `MultiTrack Prompt Enhancer` 节点改写。模板没有这个节点时，就要写完整的提示词。

## 修改写法与模块

craft.md、模块与选用层只在用户要求时修改。用户要加内容时：

- **先筛**：跟人物外貌、身材有关的偏好不收，人物长相由参考图或用户决定。光影、运镜、特效这类审美选择，或有价值但没验证、跟现有写法冲突的，说明理由，建议放进选用层，由用户决定。来源是别人的 skill 或提示词时也一样，不照单全收。
- **放哪里**：换任何画风、运镜、类型都成立，而且是模型的行为或限制的，放进 craft.md 相关的那一节，能并进现有那条就并；只在某种画风、运镜或类型成立的，放进对应的模块，没有就新建一份。指南写过的不再写。
- **模块的写法**：第一行 `适用：…`，写什么要求或素材用它；只写跟 craft.md 不同或它没有的；内容来自跑过、效果好的提示词；不写专案经过、日期或个人偏好；可附一两个短范例，提示词照指南用英文，台词保留原文。
- **删除模块或选用层的一份**就是删掉那份文件，没有别的地方要改。用户实际跑过、效果好的选用层内容，可以照用户的意思移进模块或 craft.md。
- **整理**：用户要求整理时，列出打算合并、改写、删除的地方，用户同意后才改。
